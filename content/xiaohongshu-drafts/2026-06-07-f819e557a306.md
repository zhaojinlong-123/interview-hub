## 详细解答与分析
这组题的主线不是背概念，而是判断候选人能否把 训练框架 / 推理优化 拆成可解释、可实现、可评估的工程链路。以「DeepSpeed ZeRO、Megatron 张量并行、流水并行和数据并行分别解决什么瓶颈？」为例，回答时建议先给出整体结构，再说明每个模块的取舍，最后落到项目中的指标和失败案例。

**回答结构：**
- 核心机制：先解释输入、表示、模型模块、训练目标和输出形式。
- 工程取舍：说明为什么选这个结构，而不是另一个更重或更简单的方案。
- 常见问题：主动讲清楚数据噪声、幻觉、延迟、显存、评估偏差或长尾失败。
- 验证方法：给出离线指标、人工评测、线上反馈和数据回流方式。

**简洁回答模板：**
我会先把 训练框架 / 推理优化 看成一条链路：数据输入 -> 表示学习 -> 模型连接/训练目标 -> 推理部署 -> 评估反馈。面试时不要只说模型名，要把“为什么这样设计、哪里容易失败、怎么验证有效”讲完整。

## 逐题解答

### 题目 1：DeepSpeed ZeRO、Megatron 张量并行、流水并行和数据并行分别解决什么瓶颈？

**详细回答：**

ZeRO 主要切分优化器状态、梯度和参数，解决单卡显存放不下的问题；张量并行把单层矩阵计算拆到多卡，解决单层过宽；流水并行把不同层放到不同卡，解决层数很深；数据并行复制模型、切 batch，提升吞吐但显存冗余高。

**面试展开：**

面试里不要只报名字，要说清楚通信代价：数据并行看梯度 all-reduce，张量并行看层内通信，流水并行看 bubble 和 micro-batch 调度。更完整的回答是：大模型训练通常不会只用一种并行，而是数据并行、张量并行、流水并行和 ZeRO 混合使用，用显存、吞吐、通信和工程复杂度做平衡。

### 题目 2：大模型训练中显存如何拆解到参数、梯度、优化器状态、激活值和 KV cache？

**详细回答：**

训练显存通常拆成参数、梯度、优化器状态、激活值和临时 buffer。Adam 优化器状态常常比参数本身更占空间；长序列训练时激活值会随 batch、序列长度、层数增长；推理时重点从梯度和优化器状态转到 KV cache。

**面试展开：**

常见优化手段可以按对象回答：参数和优化器状态用混合精度、ZeRO、offload；激活值用 gradient checkpointing、FlashAttention、序列并行；推理 KV cache 用分页管理、量化、prefix cache 或更短上下文策略。真正有项目经验的回答，应该能说出“我优化的是哪一块显存，以及代价是什么”。

### 题目 3：KV cache、PagedAttention、continuous batching 和 speculative decoding 如何提升推理吞吐？

**详细回答：**

KV cache 避免每次生成都重复计算历史 token 的 K/V；PagedAttention 把 KV cache 像分页内存一样管理，减少碎片并提升并发；continuous batching 让不同请求动态进入 batch，减少空等；speculative decoding 用小模型先草拟、大模型验证，降低每个 token 的平均延迟。

**面试展开：**

这题的关键是分清优化对象：KV cache 和 PagedAttention 主要管显存与复用，continuous batching 管请求调度，speculative decoding 管解码计算量。追问时可以补充风险：调度复杂度上升、长短请求混排导致尾延迟、草稿模型质量不足会降低 speculative decoding 收益。

### 题目 4：INT8/INT4 量化、AWQ/GPTQ、LoRA 合并和蒸馏分别适合哪些部署场景？

**详细回答：**

INT8/INT4 量化通过降低权重或激活精度减少显存和带宽压力；GPTQ 偏离线权重量化，适合部署前压缩；AWQ 保护重要通道，通常更关注推理质量；LoRA 合并适合把微调增量融入基座模型，减少在线额外分支；蒸馏适合把大模型能力迁移到小模型。

**面试展开：**

回答时要强调取舍：量化可能伤害长尾能力和数学/代码能力，蒸馏依赖 teacher 数据质量，LoRA 合并后切换任务不如 adapter 灵活。线上选择通常不是单点技术，而是结合目标硬件、延迟预算、质量阈值、并发量和维护成本来决定。
